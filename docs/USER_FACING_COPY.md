# User-facing language rule

All public website text must be written for normal visitors.

- Do not show developer-facing, debugging, API, database, stack-trace or implementation wording to visitors.
- Error and status messages must explain what happened and what the visitor can do next.
- Prefer short, clear, respectful language.
- Keep technical names only when they are useful to the visitor, such as “QR Code”, “Wi‑Fi”, “UPI”, or “JSON”.
- Never expose secrets, internal IDs, database names, function names, provider errors or raw server responses.
- Apply this rule to tools, forms, authentication, safety pages, navigation, downloads and future features.
